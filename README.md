# task-console

[![CI](https://github.com/eomdh/task-console/actions/workflows/ci.yml/badge.svg)](https://github.com/eomdh/task-console/actions/workflows/ci.yml)

할 일을 조회하고 삭제하는 SPA. 프론트엔드 과제 구현이다.
백엔드 없이 MSW 목 서버로 동작하며, API 계약은 `spec/openapi.yaml`을 단일 진리로 따른다.

## 데모

https://task-console-demo.vercel.app

데모 계정: `demo@example.com` / `password123`

목 서버가 프로덕션 빌드에 포함돼 있어 배포본도 로컬과 똑같이 동작한다.

## 실행

Node 22.13 이상과 pnpm 11 이상이 필요하다. `.nvmrc`에 기준 버전이 있다.
pnpm 11이 Node 22.13 미만을 거부하고, pnpm 10 이하에서는 `pnpm-workspace.yaml`의
`allowBuilds`가 맵 문법으로 인식되지 않아 lint가 깨진다.

```
pnpm install
pnpm dev
```

```
pnpm test:run     테스트 1회 실행
pnpm typecheck    타입 검사
pnpm lint         ESLint (FSD 레이어 경계 검사 포함)
pnpm build        프로덕션 빌드
pnpm gen:api      spec/openapi.yaml 에서 타입 재생성
```

## 화면

| 경로 | 화면 | 하는 일 |
| --- | --- | --- |
| `/sign-in` | 로그인 | 이메일과 비밀번호 검증, 실패 시 서버 메시지를 모달로 |
| `/` | 대시보드 | 일, 해야할 일, 한 일 개수 |
| `/task` | 할 일 목록 | 가상 스크롤과 무한 스크롤 |
| `/task/:id` | 할 일 상세 | 제목, 메모, 등록 시각과 삭제 확인 모달 |
| `/user` | 회원정보 | 이름과 메모, 로그아웃 |

로그인하지 않고 데이터 화면에 들어가면 로그인으로 보내고, 원래 목적지를 `redirect`
쿼리에 담아 로그인 후 되돌린다.

## 구조

Feature-Sliced Design을 따른다. 레이어는 위에서 아래로만 참조한다.

```
app      라우터, 프로바이더, 전역 스타일
pages    화면 조합만
widgets  화면을 구성하는 덩어리 (목록, 상세, 지표, 회원정보, GNB)
features 사용자 행위 (로그인, 삭제, 로그아웃)
entities 도메인 (task, user, dashboard, session)
shared   도메인을 모르는 것 (http 클라이언트, 가상 스크롤, 공용 UI)
```

화면 다섯 개짜리 앱에 레이어 여섯 개는 과해 보인다. 그럼에도 고른 이유는 두 가지다.

첫째, "할 일"이라는 도메인 하나를 목록, 상세, 삭제 세 화면이 나눠 쓴다. 폴더를 화면
기준으로 자르면 같은 도메인 코드가 세 곳에 흩어지고, 파일 종류 기준(`components/`,
`hooks/`)으로 자르면 도메인이 사라진다. FSD는 도메인(`entities`)과 사용자 행위
(`features`)를 나눠 이 둘을 다 피한다.

둘째, 경계를 lint로 강제할 수 있다. `eslint-plugin-boundaries`로 역방향 import,
같은 레이어 슬라이스 간 import, `index.ts`를 우회하는 깊은 경로 import를 막는다.
규칙이 문서가 아니라 빌드에서 지켜진다.

대신 파일 수가 늘어난다. 9줄짜리 `get-tasks.ts`도 전용 폴더를 갖는다. 슬라이스마다
구조가 같아야 처음 보는 슬라이스도 예측대로 읽힌다고 보고 감수했다.

## 설계 결정

요구사항과 `openapi.yaml`에 없는 부분은 아래처럼 정했다.

### 인증과 세션

- **refresh 토큰은 일반 쿠키(이름 `token`)로 전달.** openapi가 refresh를 쿠키 인증으로
  명세하는데 MSW는 httpOnly를 흉내낼 수 없다. localStorage로 우회하면 스펙에 없는 요청
  body를 지어내야 해서, 쿠키 이름까지 명세를 따르고 httpOnly만 포기했다. 해당 코드에는
  `[데모 환경]` 주석이 있다.
- **토큰 갱신은 반응형(401 이후)만.** 만료를 예측해 선제 갱신하는 방식은 시계 오차
  처리가 붙고, 401 경로는 어차피 필요해서 채택하지 않았다. 동시 401은 갱신 한 번을
  공유하고(single-flight), 재시도는 1회뿐이다.
- **세션은 부팅 때 한 번 복원.** accessToken을 메모리에만 두어 새로고침과 딥링크
  진입에서 사라진다. 이 시점에는 API 요청이 없어 401도 나지 않으므로 반응형 갱신이
  걸리지 않는다. 그래서 렌더 전에 쿠키의 refresh 토큰으로 한 번 복원한다. 복원 실패는
  만료가 아니라 비로그인 상태라 세션 만료를 알리지 않고, 라우트 가드가 로그인으로 보낸다.
- **로그아웃은 요구사항에 없지만 넣었다.** GNB는 로그인 여부에 따라 회원정보와 로그인 중
  하나를 보여야 하는데, 위의 부팅 복원을 넣은 뒤로는 쿠키가 살아 있는 한 비로그인 상태에
  닿을 방법이 사라졌다. 개발자 도구로 쿠키를 지워야만 명세된 화면을 볼 수 있게 된 셈이라,
  복원 이전과 같은 확인 경로를 되돌려주기로 했다. 버튼은 회원정보 페이지에 두어 GNB 항목
  구성은 명세 그대로 유지한다. 로그아웃 시 쿼리 캐시도 비운다. 남겨두면 다음 로그인 직후
  이전 사용자의 목록과 지표가 잠깐 보인다.

### 목록

- **가상 스크롤은 고정 카드 높이 전제.** 시작 인덱스가 이진 탐색 없이 나눗셈으로 나온다.
  카드는 line-clamp로 높이를 고정한다. 스크롤 중 바뀌는 스타일은 컨테이너 `translateY`
  하나라 reflow가 발생하지 않는다. 보조기기에는 `aria-setsize`와 `aria-posinset`으로
  전체 개수와 위치를 알린다.
- **목록 스크롤 위치는 히스토리 항목 단위로 복원.** 뒤로가기로 돌아오면 보던 위치가,
  GNB로 새로 들어오면 최상단이 나온다. 브라우저의 기본 동작과 라우터들의 규약을 따랐다.
  라우터의 스크롤 복원을 켜고 저장된 위치를 가상 스크롤의 초기 오프셋으로 넘긴다. 가상
  목록은 렌더 전에 콘텐츠 높이가 없어 `scrollTop`만 되돌려서는 위치가 맞지 않기 때문이다.
  목록이 줄어 그만큼 내려갈 수 없으면 갈 수 있는 데까지만 간다. 한 건을 지우면 줄어드는
  높이가 카드 한 장이라, 맨 끝에서 마지막 항목을 지워도 새 맨 끝에 남는다. 복원을 포기하고
  최상단으로 보내는 쪽도 검토했지만, 500건 중 하나를 지웠다고 보던 자리를 잃는 편이 더
  나쁘다고 봤다. 잘라내는 일은 브라우저와 윈도우 계산이 이미 하므로 따로 더한 코드는 없다.
- **목록 페이지 크기는 20.** 스펙에 정의가 없어 뷰포트 여러 장 분량으로 정했다.

### 상세와 삭제

- **삭제 확인 input은 라우트 파라미터와 비교.** 상세 응답(`TaskDetailResponse`)은
  `additionalProperties: false`로 닫혀 있어 title, memo, registerDatetime만 온다. id가
  없으므로 확인값은 URL의 `:id`와 맞춘다. 같은 이유로 상세 화면에는 TODO/DONE 표시가 없다.
  제공된 계약을 고쳐 필드를 늘리는 대신 없는 정보를 지어내지 않는 쪽을 택했다.
- **상세에서 목록으로는 뒤로가기로 이동.** 보던 위치를 지키기 위해서다. 딥링크로 들어와
  돌아갈 항목이 없을 때만 목록 경로로 보낸다. 로그인을 거쳐 상세에 들어온 경우를 위해
  로그인 성공은 push가 아니라 replace로 처리한다. 그러지 않으면 뒤로가기 한 칸이 목록이
  아니라 로그인 화면이 된다.
- **삭제 후에는 뒤로가기를 쓰지 않고 목록 경로로 보낸다.** 요구사항이 "목록으로 redirect"를
  문구로 정했는데, 뒤로가기는 직전 항목이 목록이라는 가정에 기댄다. 대시보드나 회원정보를
  거쳐 상세에 들어왔다면 그 가정이 깨져 엉뚱한 화면에 떨어지고, 삭제 안내도 목록에서만
  뜨므로 함께 유실된다. replace로 보내 지운 항목의 상세가 히스토리에서 빠지는 대신,
  삭제 후 목록은 최상단에서 시작한다.
- **삭제 후에는 목록 캐시를 통째로 무효화.** offset 페이지네이션이라 한 건이 지워지면 뒤
  항목이 한 칸씩 당겨진다. 캐시에서 항목만 빼면 다음 페이지를 받을 때 경계에서 한 건이
  누락된다. 이미 받아둔 페이지를 다시 받는 비용은 이 정합성과 맞바꿨다.

### 스펙 해석

- **비로그인 보호 라우트는 로그인으로 리다이렉트.** 모든 데이터 API가 bearer 필수라
  비로그인 화면은 어차피 비어 있다.
- **비밀번호 규칙은 허용 문자 집합으로 해석.** 요구사항의 "영문, 숫자로 구성된 8글자 이상
  24글자 이하"는 둘 다 반드시 포함해야 하는지 모호한데, openapi 패턴(`^[A-Za-z0-9]+$`)이
  허용 집합만 강제하므로 명세를 따랐다.
- **회원정보 경로는 `/user`.** 요구사항이 경로를 명시하지 않아 API 경로를 따랐다.
- **내비게이션은 상단 GNB.** 요구사항 표기는 GNB/LNB인데 항목이 3개뿐이라 상단 바 하나로
  충분하다.

### 스택

- **라우터는 TanStack Router.** React Router가 기본값이지만 두 가지가 필요했다. 검색
  파라미터를 타입으로 검증하는 `validateSearch`(로그인 복귀 경로 `redirect`가 여기 걸린다),
  그리고 스크롤 위치를 히스토리 항목 단위로 캐시하는 `useElementScrollRestoration`
  (가상 스크롤 목록의 위치 복원에 쓴다). 둘 다 React Router에서는 직접 만들어야 한다.
  같은 팀의 TanStack Query를 이미 쓰고 있어 학습 비용도 낮았다.
- **라우팅은 코드 기반.** TanStack Router의 파일 기반 라우팅은 `src/routes/` 디렉토리를
  강제해 FSD의 `pages` 레이어와 역할이 겹친다. 라우트 트리를 `app/router.tsx`에 두고
  `pages`를 조합한다.
- **서버 상태는 TanStack Query.** 캐시와 로딩/에러 상태, 무한 스크롤(`useInfiniteQuery`)을
  표준 패턴으로 처리한다. Query 레벨 재시도는 껐다. 401 갱신 재시도를 http 클라이언트가
  이미 담당해 이중 재시도를 피하기 위함이다.
- **목 서버는 프로덕션 빌드에도 들어간다.** 백엔드가 없어 배포본에서도 MSW worker를 띄운다.
  그래서 산출물에 gzip 158KB가 더 붙는다(앱 코드는 132KB). 실제 서비스라면 `app/main.tsx`의
  worker 기동 블록이 통째로 사라지고 이 무게도 같이 사라진다. 해당 블록에는 `[데모 환경]`
  주석이 있다.
- **TypeScript 6 고정.** typescript-eslint가 TS 7을 아직 지원하지 않는다. lint가 완료 기준
  게이트라 TS를 내렸다.

### 스타일

- **디자인 규칙 체계는 StyleSeed 오픈소스를 참고.** 한 accent + 그레이스케일, 순수 검정 금지,
  8px 그리드, soft 배경 변형 같은 규칙을 가져왔고 팔레트는 직접 구성했다(accent `#2563EB`,
  그레이는 Tailwind 스케일). 값과 규칙은 `.styleseed/STYLESEED.md`에 잠가두었다. 라이트
  테마만 지원한다.
- **hover는 한 단계만 움직인다.** 무엇이 움직이는지는 요소가 가진 것에 따라 다르다. 배경이
  없던 GNB 링크는 배경이 생기고, 배경과 테두리를 가진 카드와 ghost 버튼은 테두리와 배경을
  함께 한 단계 내리고, 배경만 가진 채운 버튼은 배경이 어두워진다. accent는 현재 페이지와
  포커스에 이미 쓰므로 hover에 쓰지 않는다.
- **Pretendard는 동적 서브셋으로 받는다.** 통짜 variable 파일이 2.0MB라 산출물에서 가장
  무거운 자산이었다. 같은 패키지의 동적 서브셋으로 바꾸면 `unicode-range`로 쪼갠 조각 중
  화면에 실제 나온 글자가 속한 것만 받는다. 첫 화면은 3조각 79KB, 목록 500건을 끝까지
  훑어도 8조각 203KB다. 대신 `@font-face` 규칙이 92개로 늘어 CSS가 gzip 기준 4KB에서
  19KB가 된다. 그 비용을 치를 만한 교환으로 봤다.

## 테스트

13개 파일 74건. MSW 핸들러 하나를 브라우저(`setupWorker`)와 테스트(`setupServer`)가
공유한다. 목이 두 벌이면 스펙이 갈라진다.

난이도가 높은 두 곳은 실패하는 테스트를 먼저 커밋한 뒤 통과 커밋을 쌓았다. 스펙을 먼저
확정하기 위해서다.

- 가상 스크롤 렌더 윈도우 계산 (`shared/lib/virtual`, 16건)
- 401 토큰 갱신과 원요청 재시도 (`shared/lib/http`, 7건)

나머지는 사용자가 보는 동작을 검증한다. 목 서버 계약 14건, 화면 단위 동작 31건,
모달 포커스 트랩과 세션 복원 6건이다.

커밋마다 GitHub Actions가 같은 게이트(typecheck, lint, test:run)와 프로덕션 빌드를
돌린다. Node와 pnpm 버전은 워크플로에 적지 않고 `.nvmrc`와 `package.json`의
`packageManager`를 읽어, 로컬과 CI가 같은 값을 쓴다.

## 알려진 한계

- **뷰포트 높이는 마운트 시 1회만 잰다.** 창 크기를 키우면 스크롤하기 전까지 목록 하단에
  빈 영역이 남는다. `ResizeObserver`를 붙이면 해결되지만 스크롤 경로에 관측자가 하나
  늘어난다.
- **Tab으로 목록을 훑다 포커스된 카드가 렌더 윈도우 밖으로 나가면 포커스가 유실된다.**
  스크롤 영역 자체는 키보드로 스크롤할 수 있다.
- **overscan(카드 5장)을 한 프레임에 넘는 빠른 플릭에서는 빈 영역이 잠깐 보인다.**
- **입력창 테두리 대비가 1.24:1이다.** WCAG 1.4.11이 폼 컨트롤 경계에 요구하는 3:1에
  못 미친다. 3:1을 맞추려면 팔레트의 `line` 값을 상당히 어둡게 내려야 하고 화면 인상이
  크게 바뀐다. 텍스트 대비는 전부 4.5:1 이상을 지킨다.
- **시드는 메모리에 있다.** 새로고침하면 삭제한 항목이 되살아나고 스크롤 위치도 초기화된다.
  로컬과 배포본이 같다.
- **목록에 다시 들어오면 받아둔 페이지를 전부 다시 받는다.** 삭제 정합성 때문에 캐시를
  통째로 무효화하는 선택의 대가다. 화면은 캐시로 유지돼 끊김은 없다.
- **반응형은 GNB만 대응한다.** 요구사항에 없어 좁은 화면에서 GNB가 넘치지 않는 선까지만
  손봤다.
